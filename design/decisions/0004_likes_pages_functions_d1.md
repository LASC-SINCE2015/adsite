# 0004 いいねボタンの数は Cloudflare Pages Functions と D1 で保存する

- 状態: 採用
- 日付: 2026-11-15

## 状況

作品カードに「いいね」ボタンを付け、作品ごとの数をみんなで共有したい。数を保存するサーバー側の仕組みが必要になる。条件は、完全無料で、上限を超えても請求が発生しないこと。サイトはビルドなしの静的ファイル（[ADR 0002](0002_static_html_no_build.md)）のまま保ちたい。

## 決定

- API は Cloudflare Pages Functions（リポジトリの `functions/`）で作り、数は Cloudflare D1 に保存する。
- D1 は本番用とプレビュー用を分け、Pages のプロジェクトに変数名 `LIKES_DB` で結び付ける。
- 閲覧者を見分ける情報（IP アドレス・Cookie など）はサーバーに保存しない。同じ人の連打は、ブラウザの localStorage に「いいね済み」を覚えて防ぐ程度にとどめる。

## 理由

- Pages Functions と D1 は、すでに使っている Cloudflare Pages のプロジェクトに追加するだけで使え、新しいサービスの登録がいらない。
- どちらも無料枠（Functions は Workers の 1 日 10 万リクエスト、D1 は 1 日 10 万行の書き込みなど）があり、カードを登録していないので超えてもエラーになるだけで請求は来ない。
- `functions/` は Cloudflare Pages が自動で取り込むため、ビルドコマンドを設定しなくてよい。サイト本体は静的ファイルのまま。
- Phase 2 で予定している Supabase を待たずに作れる。数を数えるだけなら D1 で足りる。

## 影響

- いいねボタンは「上乗せ」の機能にする。API が動かない環境（ローカルの静的サーバーなど）では、ボタンを出さない。
- localStorage を消したり別のブラウザを使ったりすれば、何度でもいいねできる。数は厳密な人数ではなく、目安として扱う。いたずらが目立つようになったら、回数制限などを検討する。
- プライバシーポリシーに、いいねボタンで送る情報とローカルストレージの利用を書いた。
- いいねの数はアクセス解析と合わせて、作品の人気を見る材料にできる。
